# E Ink 贈品庫存管理系統

登記贈品的拿出與補入、定期盤點，一頁看清庫存數量與低庫存狀況。每一筆異動都留下記錄，記錄不能刪除，只能沖銷。

- **網站**：https://p60732.github.io/eink-gifts/
- **資料**：Google 試算表「eink禮品庫存」
- **後端**：綁定在試算表上的 Apps Script（專案名稱「kim贈品庫存」），部署成網頁應用程式
- **圖片**：存在雲端硬碟「eink贈品圖片」資料夾
- **備份**：每週一早上 7 點自動備份到雲端硬碟「eink贈品備份」資料夾，保留最近 26 份（約半年）
- **寄送備份**：每年 1/1、7/1 早上 8 點自動把備份 Excel（庫存、異動記錄、盤點，不含人員名單）寄到「設定」分頁的「備份寄送信箱」；空白時寄給試算表擁有者

## 日常操作

### 登入與權限
輸入「管理者」名單裡、已啟用的名稱（工號）即可登入。登入 6 小時後會自動登出。

| | 一般人員 | 可管理人員 |
|---|---|---|
| 拿出贈品、補入庫存 | ✓ | ✓ |
| 看庫存、異動記錄、匯出 | ✓ | ✓ |
| 沖銷 | 只能沖銷自己登打的 | 任何人的都可以 |
| 新增／編輯／刪除品項、匯入 | | ✓ |
| 盤點 | | ✓ |
| 人員管理（新增人員、給予管理權限） | | ✓ |

一般人員看不到「新增品項」「匯入」「盤點」和品項的編輯、刪除按鈕。在人員管理改了某人的權限後，對方要重新登入才會套用（系統會自動讓他登出）。

### 拿出贈品／補入庫存
按上方「拿出贈品」或「補入庫存」→ 選品項 → 輸入數量 → 可填備註（發給誰、哪個活動）→ 確認。
操作者會自動記成登入的名稱。

### 新增／編輯品項
- **新增品項**：填品名、期初數量、單位、低庫存警示、備註，可以上傳照片。
- **編輯**：可以改品名、單位、警示值、備註、照片。**數量不能在這裡改**，一定要透過拿出、補入或盤點，才會留下記錄。
- **刪除**：刪除本身會留下記錄；刪除過的編號不會再給新品項使用。
  - 剛新增、還沒有任何拿出／補入的品項（例如不小心重複新增），可以連同期初數量直接刪除。
  - 已經有其他異動的品項，要先用拿出或盤點歸零才能刪除。
  - 進行中的盤點單裡已輸入實點的品項，要先清除該項才能刪除。
- **同名提醒**：新增或改名時，如果已經有同名的品項（忽略空白與全半形括號），會先詢問是否確定。

### 異動記錄
「異動記錄」分頁預設顯示全部品項最新 20 筆，上方的類型列往下捲動時會固定在畫面頂端，按「顯示更多」再載入 20 筆。上方可以依類型（領用、補貨、新增品項、刪除品項、沖銷、盤點調整）分類，也可以再依品項或日期篩選；開分頁時會先顯示上次看到的記錄（標示「同步中」，這時不能沖銷），再更新成最新的。「匯出」會下載符合條件的記錄，一次最多 5000 筆；超過時會提示，請用日期篩選分段匯出。

### 登打錯了怎麼辦：沖銷
記錄不能刪除。在該筆「領用」或「補貨」記錄按「沖銷」並填寫原因，系統會新增一筆反向記錄，並把庫存調回去；原本那筆會標示「已被 Lxxxxx 沖銷」。

### 盤點（建議每半年一次）
1. 「盤點」分頁 →「開始盤點」，輸入盤點名稱（例如「2026 Q4 盤點」）。建立後畫面會直接列出目前全部品項與帳面數量。可以按右上「列印盤點表」印出來帶去現場點；手機無法列印時，按「下載盤點表 Excel」。還沒開始前也能先印一份空白盤點表。
2. 逐項輸入實際點到的數量，系統會自動算出差異。盤點期間照常可以拿出、補入，差異會以輸入當下的帳面數量計算。輸錯了可以直接改數字；把數字清空就會改回「未盤」。
3. 確認無誤後按「完成盤點」，系統才會一次寫入「盤點調整」記錄。完成前隨時可以修改或取消。
4. 盤點分頁上方會顯示上次完成盤點的日期；超過半年會以紅字提醒。

### Excel 匯出／匯入
- **匯出**：下載目前庫存。
- **全部匯出**（可管理人員）：庫存、全部異動記錄（由舊到新）、盤點記錄一次下載成一個 Excel，當作自己保存的備份。建議每月一次，存在自己電腦或公司硬碟。
- **匯入**：欄位需包含「品名」。有對應 ID 的列會更新該品項，ID 空白的列會新增品項。建議先匯出當範本再修改。

## 管理（需要「可管理人員」權限）

在「設定」裡：

- **人員管理**：新增人員、改名、啟用／停用、給予或拿掉管理權限（權限內容見上方「登入與權限」）。人員不能刪除，只能停用。不能停用自己，也至少要保留一位可管理人員。停用、改名或重設密碼後，對方目前的登入會立即失效。
- **最後自動備份**：顯示最近一次備份的日期；超過一週沒備份會以紅字提醒。
- **後端網址**：只有重建後端時才需要修改，平常不要動。

### 試算表「設定」分頁的開關

| 設定項目 | 說明 |
|---|---|
| 需要登入 | 勾選＝要登入才能使用；取消勾選＝任何知道網址的人都能拿出、補入（不能編輯品項或盤點），操作者記為「免登入操作者」 |
| 登入需要密碼 | 勾選＝**可管理人員**要名稱＋密碼，一般人員仍只輸入工號；取消勾選＝大家都只要名稱在名單內即可。打開後，可管理人員先前只用名稱的登入會被登出，需要用密碼重新登入；在密碼模式下把某人升為可管理人員，系統會給一組一次性初始碼 |
| 免登入操作者 | 免登入模式下，異動記錄上的操作者名稱 |
| 圖片資料夾ID／備份資料夾ID | 系統自動填寫，不用改 |
| 最後備份 | 系統自動填寫 |
| 備份寄送信箱 | 每半年寄備份 Excel 的收件人，多個用逗號分隔；空白 = 寄給試算表擁有者 |
| 最後寄送備份 | 系統自動填寫 |

> 直接在試算表修改設定、人員或庫存時，網頁最多要 1～2 分鐘才會反映（為了加快速度有做快取）。從網頁操作的變更會立即生效。

## 系統架構

```
瀏覽器（GitHub Pages：index.html）
   │  POST JSON（只用 POST；登入後以權杖驗證）
   ▼
Apps Script 網頁應用程式（Code.gs）
   │
   ├─ 試算表：庫存／異動記錄／設定／管理者／盤點／盤點明細
   ├─ 雲端硬碟：eink贈品圖片、eink贈品備份
   └─ 快取（CacheService）：登入權杖、設定、人員權限、庫存清單、最新 20 筆記錄
```

**速度相關設計**

- 開頁時會先顯示上次的庫存（標示「同步中」），再向後端取最新資料。
- 異動記錄由後端分頁，每次只讀 20 筆；有篩選時只讀篩選用的那一欄（時間／品項／類型）找出符合的列，再只讀這一頁的列。
- 盤點分頁會先顯示上次的資料（標示「同步中」，這時不能輸入），再更新；盤點明細只讀「盤點ID」一欄找出這張單的範圍，再只讀那幾列，而且有快取。
- 「已沖銷」標示只讀這一頁到最新記錄之間的兩欄；沖銷時用記錄ID直接找到那一列（Lxxxxx 的數字＋1 就是列號）。
- 讀取類操作不需要排隊；寫入類操作會上鎖，避免同時寫入衝突。
- 讀取 10 秒沒回應會自動重試一次。
- 新增品項、拿出、補入、匯入每次送出都帶一個「送出編號」，後端記住 30 分鐘：同樣內容重按或網路慢時自動重送，都只會登記一次。這幾個動作 30 秒沒回應會自動重送一次。
- Google 偶爾會把請求轉成一般網頁瀏覽（伺服器什麼都沒做，回傳「請使用贈品庫存網頁」），網頁會自動重送一次，讀取和寫入都安全。

**工作表欄位**

- **庫存**：ID、品名、數量、單位、低庫存警示、備註、最後更新、圖片
- **異動記錄**：時間、品項ID、品名、變動量、變動後數量、備註、操作者、類型、記錄ID、沖銷對象
- **管理者**：名稱、啟用、初始碼、密碼雜湊、鹽、最後登入、說明、可管理人員
- **盤點**／**盤點明細**：盤點單與每個品項的帳面、實點與差異

## 維護者須知

### 修改後端（Code.gs）
1. 開啟試算表 → 擴充功能 → Apps Script。
2. 貼上新的程式碼 → 儲存。
3. 部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「建立新版本」→ 部署。網址不會變。

**退回舊版**：同一個畫面把版本改回前一版，再按部署即可。

### 修改前端（index.html）
上傳到這個 repo 的 main 分支，約 1 分鐘後網站就會更新（瀏覽器可能要重新整理）。

### 只能在 Apps Script 編輯器執行的函式（限試算表擁有者）

| 函式 | 用途 |
|---|---|
| `setupWeeklyBackup` | 建立每週自動備份，並立刻先備份一份（只需執行一次） |
| `backupSpreadsheet` | 手動立刻備份一份 |
| `setupHalfYearMail` | 建立每半年寄出備份 Excel 的排程，並立刻寄一封確認（只需執行一次；第一次會要求授權「寄送電子郵件」與「連線到外部服務」） |
| `mailBackupExcel` | 手動立刻寄出一次備份 Excel |
| `generateInitCodes` | 在密碼模式下，為新人員產生一次性初始碼 |

> 在編輯器執行函式前，請先確認上方函式選單已完全關閉、顯示的是要執行的函式名稱，再按「執行」。選單偶爾會顯示 A 卻執行 B。

### 從備份還原
到雲端硬碟「eink贈品備份」找到要還原的日期，開啟後把需要的工作表內容複製回正式試算表。**不要直接把備份檔當成正式檔使用**，因為網頁後端綁在原本的試算表上。

### 移交給其他人
試算表、Apps Script 和備份資料夾目前都在建立者的個人 Google 帳號下，這個 GitHub repo 也是個人帳號。正式移交時需要：
1. 把試算表（連同綁定的 Apps Script）的擁有權轉給接手者，或搬到公司帳號後重新部署。
2. 如果後端網址變了，更新 `index.html` 的 `DEFAULT_API_URL`。
3. 由新的擁有者重新執行一次 `setupWeeklyBackup`（觸發條件不會跟著轉移）。
